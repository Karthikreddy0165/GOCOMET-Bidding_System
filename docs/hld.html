Request and Bidding Flow

End-to-end procurement flow from RFQ setup to auction settlement.

STEP 01
Configure RFQ
Buyer defines cargo lane, baseline price, bidding start time, initial close time, forced close ceiling, and extension parameters (trigger window and increment).
STEP 02
Publish & Activate
RFQ activates automatically at its scheduled start time. Invited suppliers view cargo specifications and the current countdown clock.
STEP 03
Supplier Quotes
Suppliers submit landed freight quotes (base freight, bunker, terminal charges, doc fees), transit days, and quote validity dates.
STEP 04
Evaluate & Extend
Incoming bids are evaluated in an atomic row lock. If placed inside the trigger window, close time extends by increment minutes, capped at the forced close time.
STEP 05
Conclude & Award
Auction closes at current deadline or forced close ceiling. Lowest qualified bidder (L1) wins based on price, transit time, and timestamp.

Role-Based Access Control (RBAC) & Service Responsibilities

Unified application design with strict security boundaries between Buyers, Suppliers, and Admins.

SECURITY & PERMISSIONS
Unified Web App with RBAC
Rather than maintaining two disconnected sites, the system runs as a single web application where access and navigation are governed by user roles:
  • Role: BUYER: Can create RFQs, configure anti-sniping trigger rules, set forced close deadlines, invite suppliers, review competitor identities, and inspect full audit logs.
  • Role: SUPPLIER: Enters the supplier bidding platform. Can submit and revise freight quotes, enter transit times, and view real-time rank positions.
  • Role: ADMIN: Platform-wide supervision, user management, and auction lifecycle overrides.
ANTI-SNIPING PRIVACY
Information Asymmetry by Role
To maintain fair competition and prevent game-theoretic last-second bid sniping:
  • Visible to Suppliers: Current visible closing time, baseline price, their own landed cost breakdown, and their calculated rank (e.g. L1, L2).
  • Hidden from Suppliers: The forced close ceiling and the buyer's extension trigger window are never sent to supplier clients.
  • WebSocket Sanitization: Real-time push events dynamically sanitize payload data so suppliers never see rival company names or bid values.
RANKING LOGIC
Multi-Attribute Winner Ranking
Commercial logistics procurement evaluates both cost and transit speed in strict order:
  • Primary: Lowest Total Price: Landed cost (base freight + bunker + terminal + doc fees) determines rank. Lowest amount is L1.
  • Tie-Breaker 1: Shorter Transit Time: If two suppliers submit the same total amount, the supplier offering shorter transit duration wins the tie.
  • Tie-Breaker 2: Submission Timestamp: If price and transit time are identical, the earlier submitted bid takes priority.
CONCURRENCY & INTEGRITY
Atomic Bid Processing & Row Locking
When multiple suppliers submit bids in the final seconds of an auction:
  • The backend acquires a database transaction lock on the target auction record before evaluating time extensions.
  • Only one bid updates the deadline at a time, preventing double extensions and lost updates.
  • Client-provided idempotency keys prevent accidental duplicate quotes caused by network retries.

Business Invariants

Core integrity rules enforced across the platform.

INVARIANT 01
Single Active Auction per Name
Only one active or scheduled auction may exist with a given name at any time. When an auction is closed or completed, a new auction may reuse the name. This prevents buyer confusion and duplicate bidding rooms.
INVARIANT 02
Single-Supplier Same-Bid Prevention
A supplier cannot submit the exact same landed cost quote twice within the same auction. They must submit a lower rate or an improved commercial offer. However, two different competing suppliers may quote identical amounts, which is resolved via transit time tie-breaking.
